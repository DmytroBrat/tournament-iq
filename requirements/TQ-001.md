# TQ-001 — Constraint-Based Round-Robin Schedule Generation

## Business Context

TournamentIQ currently allows organizers to manage football tournaments, teams, fields and manually scheduled matches.

Manual scheduling becomes time-consuming and error-prone when multiple teams, playing fields, time windows and minimum rest requirements must be considered.

## User Story

As a tournament organizer, I want to automatically generate a valid round-robin match schedule so that I can organize a tournament without scheduling conflicts or insufficient team rest.

## Functional Requirements

### Fixture Generation

- Support single round-robin tournaments.
- Support 2 to 12 teams, including odd-sized tournaments.
- Each team must play every other team exactly once.
- Generate exactly N × (N − 1) / 2 matches.

### Scheduling Configuration

Allow the organizer to configure:

- Tournament dates.
- Daily playing time window.
- Available registered fields.
- Match duration.
- Minimum rest between consecutive matches.
- Five-minute field turnaround interval.

### Hard Constraints

- No overlapping matches for the same team.
- No overlapping matches on the same field.
- Field turnaround intervals must be respected.
- Minimum team rest must be measured from the end of one match to the start of the next.
- All matches must fit within configured dates and playing windows.
- Teams and fields must belong to the selected tournament.
- Every match must contain two distinct teams.
- No duplicate pairings.

### User Experience

- Provide a schedule generation form.
- Generate a schedule preview without persisting it.
- Display matches and a schedule validation report.
- Allow the organizer to save a valid schedule.
- Provide actionable error messages when generation fails.

### Failure Handling

- Reject invalid configuration.
- Report insufficient theoretical capacity.
- Distinguish algorithmic failure from proven infeasibility.
- Never persist an incomplete or invalid schedule.
- Never silently overwrite existing matches.

## Non-Functional Requirements

- Deterministic generation for identical normalized inputs.
- Independent schedule validation.
- Bounded execution.
- Atomic persistence.
- Scheduling domain logic independent of Spring and JPA.
- No additional infrastructure or paid services.

## Acceptance Criteria

AC-01: Eight teams produce exactly 28 unique matches.

AC-02: Odd-sized tournaments produce the correct number of fixtures without dummy-team matches.

AC-03: No team has overlapping matches.

AC-04: No field has overlapping matches or turnaround violations.

AC-05: Minimum team rest is respected.

AC-06: All matches are within allowed dates and daily time windows.

AC-07: Identical inputs produce identical schedules.

AC-08: Invalid or unsuccessful generation does not persist partial data.

AC-09: Invalid configuration produces meaningful validation errors.

AC-10: Valid schedules can be previewed and saved atomically.

AC-11: Existing matches are not silently overwritten.

AC-12: Automated verification and architecture documentation are updated.

## Out of Scope

- Knockout stages.
- Group-stage tournaments.
- Global schedule optimization.
- Guaranteed discovery of all feasible schedules.
- Referee assignments.
- Team-specific availability.
- Maximum daily matches per team.
- Automatic rescheduling.
- Live scoring.
- Authentication.
- External integrations.

## Deliverables

- Working backend and frontend functionality.
- Automated verification of business invariants.
- Documented algorithm selection and limitations.
- ArtiSyn lifecycle artifacts.
- Reproducible local demonstration.
